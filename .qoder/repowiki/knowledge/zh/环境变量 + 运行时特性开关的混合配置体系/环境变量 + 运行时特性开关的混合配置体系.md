## 1. 总体方案

本仓库采用**“启动时环境变量 + 运行时数据库特性开关”**的双层配置模型：
- **应用级配置**（数据库、密钥、第三方服务、存储后端、代理等）通过 `process.env` 加载，集中暴露于 `api/lib/env.ts`。
- **功能开关（Feature Flags）** 存储在 MySQL 的 `featureFlags` 表中，由 `api/plugins/featureFlags.ts` 提供带缓存的查询 API，供插件注册、MCP 工具、路由等按需启用。
- **订阅计划能力集** 以代码常量形式定义在 `api/config/plans.ts`，价格 ID 来自环境变量，形成“代码能力表 + 外部价格”的组合。

该模式没有引入外部配置中心或 .env schema 校验库，而是用简单的 `required()` / `validateSecret()` 函数实现最小化的强制与安全检查。

## 2. 关键文件

| 文件 | 职责 |
|---|---|
| `.env.example` | 所有环境变量的清单与注释，是部署时的权威参考 |
| `api/lib/env.ts` | 唯一的环境变量入口：定义 `required()`、`validateSecret()`，导出统一 `env` 对象 |
| `api/plugins/featureFlags.ts` | 从 `featureFlags` 表读取并缓存特性开关，提供 `isFeatureEnabled`、`seedDefaultFlags` |
| `api/config/plans.ts` | 订阅计划目录与能力集映射，价格 ID 取自 `env.stripePrice*` |
| `drizzle.config.ts` | Drizzle CLI 依赖 `DATABASE_URL`，缺失则直接抛错 |
| `ecosystem.config.cjs` | PM2 进程守护配置，注入 `NODE_ENV=production`、`PORT`、`NODE_OPTIONS` |
| `docker-compose.yml` | 本地开发时注入 MySQL、Redis 及示例 `DATABASE_URL` |
| `vite.config.ts` | 设置 `envDir` 指向仓库根，使 Vite/Hono dev server 能加载 `.env` |

## 3. 架构与约定

### 3.1 环境变量分层
- **必需项**：`APP_ID`、`APP_SECRET`、`DATABASE_URL`、`AI_SWARM_MASTER_KEY`、`MARKETPLACE_MASTER_KEY`。在 `NODE_ENV === 'production'` 下缺失会直接抛错阻止启动。
- **可选基础设施**：`REDIS_URL`、`STRIPE_*`、`SENTRY_DSN`、`S3_*`、`BACKUP_TOKEN` 等，未配置时模块降级为内存/本地磁盘/503 响应。
- **安全校验**：`validateSecret` 拒绝已知开发默认值（如 `dev-app-secret-change-in-production`），防止误部署。
- **前端可见变量**：`VITE_APP_ID` 通过 Vite 注入前端；其余仅后端使用。

### 3.2 特性开关（Feature Flags）
- 数据源：Drizzle 表 `featureFlags`（key, enabled, rolloutPercent, allowedUserIds）。
- 缓存策略：进程内 Map 缓存，TTL 60s，避免每次请求查库。
- 评估顺序：`enabled=true` → 按 `rolloutPercent` 基于 userId 哈希分桶 → 检查 `allowedUserIds` → 默认拒绝。
- 默认种子：`seedDefaultFlags` 在首次启动时写入 circuit_breaker、local_folder、marketplace_ai_triage、batch_mode、pipeline_chaining 等标志。
- 使用方：插件注册表、MCP 工具（designPipeline/help/relay）、admin 路由等通过 `isFeatureEnabled(flagKey, userId)` 调用。

### 3.3 订阅计划配置
- `PLANS` 字典将 `solo`、`team_seat` 两个 PlanId 映射到 Stripe priceId（来自 `env.stripePriceSolo` / `stripePriceTeamSeat`）。
- `PLAN_CAPABILITIES` 将 plan 名映射到能力集合（如 `llm:1`、`pipeline:custom`、`team:collaborate`），用于 entitlements 计算。
- `listPublicPlans()` 对外暴露不含敏感 priceId 的计划列表，并根据 priceId 是否为空标记 `available`。

### 3.4 构建期与环境绑定
- `vite.config.ts` 通过 `envDir: path.resolve(__dirname)` 指定 `.env` 位置，使 Hono dev server 和前端共享同一份环境变量。
- `drizzle.config.ts` 要求 `DATABASE_URL` 存在，否则 drizzle-kit 命令直接失败。
- PM2 配置文件 `ecosystem.config.cjs` 固定 `NODE_ENV=production`、`PORT=3000`、`NODE_OPTIONS="--max-old-space-size=256"`，作为生产运行时的兜底配置。

## 4. 约定与约束

- **环境变量必须通过 `api/lib/env.ts` 访问**：所有模块导入 `env` 对象而非直接读 `process.env`，保证 required/validation 逻辑集中生效。
- **生产环境禁止使用默认密钥**：`APP_SECRET` 若等于 `dev-app-secret-change-in-production` 或空，生产启动即抛错。
- **可选能力遵循“无配置即禁用”原则**：Redis、Stripe、S3、Sentry、AI Triage、Backup 等均未配置时返回降级行为（内存队列、503、本地磁盘、跳过 triage），不会导致崩溃。
- **特性开关默认关闭新能力**：`batch_mode`、`pipeline_chaining` 初始 `enabled=false`、`rolloutPercent=0`，需显式开启。
- **AI Triage 为非门控（non-gating）**：即使未配置或 flag 关闭，市场提交仍走人工审核流程，不会被阻断。
- **上传存储二选一**：配置全部 `S3_*` 字段才启用 S3 兼容存储，否则回退到 `SCREENSHOT_DIR`（默认 `./feedback-screenshots`）。
- **信任代理默认开启**：`TRUSTED_PROXY` 默认为 true，仅在直接暴露给公网且无边缘代理时才设为 false。
- **Drizzle CLI 强依赖 `DATABASE_URL`**：任何 `drizzle-*` 命令都要求该变量存在，否则立即报错。
- **PM2 限制单进程与堆大小**：`instances: 1`、`max_memory_restart: "280M"`、`NODE_OPTIONS="--max-old-space-size=256"`，适配低配实例。
