模块以 `base.ts` 中定义的 `LLMProviderAdapter` 接口为核心契约，统一抽象出 `chat`/`validateKey`/`listModels` 三个方法及 `ChatMessage`、`ChatOptions`、`ChatResponse`、`ContentPart` 等共享类型；`index.ts` 作为工厂入口 `createProviderAdapter(slug, apiKey, baseUrl, defaultModel)`，通过 slug 路由到具体适配器实现，并在 `getProviderDefaults` 中集中维护 openai、anthropic、deepseek、kimi、together、aliyun、gemini、mistral、minimax 等提供商的默认名称、baseUrl 与支持的模型列表；`openai.ts` 实现 OpenAI 兼容协议的适配器（POST `/chat/completions`，Bearer 鉴权），并通过 `formatProviderError` 将不同上游的错误码按 providerName/status 分支映射为用户可读提示，同时自动重试 `max_tokens` → `max_completion_tokens` 参数切换；`anthropic.ts` 实现 Anthropic Messages API 适配器（POST `/messages`，`x-api-key` + `anthropic-version` 头），负责把通用 `ContentPart[]` 多模态内容转换为 Anthropic 的 ContentBlock 格式，并将 system prompt 单独提取为顶层字段。依赖方向单向：具体适配器仅依赖 `base.ts` 的类型定义，由 `index.ts` 聚合导出，对外暴露统一工厂函数。
