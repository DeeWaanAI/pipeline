模块以 Hono 应用为入口，`register.ts` 挂载 OAuth 2.1 端点（`/.well-known/*`、`/oauth/*`）与受保护路由 `/mcp`、`/mcp/sse`、`/mcp/messages`，并通过 `mcpGate` 中间件完成 Bearer Token 鉴权、按客户 tier 的速率限制以及将 `McpAuthContext` 注入上下文。

- `transport.ts`：维护进程内 session map（带 TTL 清理），分别用 `StreamableHTTPServerTransport`（MCP 2025-03-26）和 `SSEServerTransport`（MCP 2024-11-05）处理请求；在 session 初始化后将 `sessionId` 与采样桥接函数挂到 `auth.runtime`，供工具反向调用客户端 LLM。
- `server.ts`：`createMcpServer(auth)` 返回延迟连接的 `DeferredMcpServer`，每次连接时根据 `tools/index.ts` 中的 `TOOLS` 列表逐个注册，并在注册前执行权限 scope 检查与可选的 featureFlag 门控（失败则隐藏该工具）；每个工具调用通过 `recordToolCall` 异步写入 `mcpAuditLog` 与 `usageCounters`。
- `types.ts`：定义跨 worker 共享的 `McpAuthContext` 与 `McpTool` 契约（name/description/zod inputSchema/scopes/featureFlag/annotations/handler）。
- `auth.ts`：自包含的 OAuth 授权服务器实现，支持 RFC 9728/8414/7591 元数据、动态客户端注册、PKCE S256 授权码流程与 refresh_token 轮换。
- `tools/`：扁平的工具集合，按功能分组（pipeline、marketplace、team、batch、portability 等），由 `index.ts` 统一导出；`_memoryStore.ts`、`_shared.ts` 提供进程内内存存储与共享逻辑；`team/` 子目录下的工具统一标记 `featureFlag: 'teamsync'` 以灰度发布。
依赖方向：`register → transport → server → tools`，`auth` 独立于运行时；工具仅依赖 `../queries/connection`、`@db/schema` 与业务服务，不感知 HTTP/MCP 协议。
