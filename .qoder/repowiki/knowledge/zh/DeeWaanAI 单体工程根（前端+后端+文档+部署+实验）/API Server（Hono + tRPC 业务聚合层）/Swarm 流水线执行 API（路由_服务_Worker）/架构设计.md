模块按三层职责划分：
- `api/routers/swarm.ts` 暴露 tRPC 路由（prepareRun/getPipeline/execute/resumePipeline/approveStep/cancelRun/getRun/listRuns/getRunStatus/executeAgent/runBatch 等），仅负责输入校验（zod + @contracts）、项目访问控制（canAccessProject 单 JOIN 查询）、速率限制（rateLimiter）以及把运行参数写入 swarm_runs.runParams 后调用 enqueueSwarmRun 入队，不阻塞请求。
- `api/services/swarmService.ts` 是真正的流水线引擎：loadPipelineSteps 从 pipelineSteps/customAgents 解析 ResolvedStep；runExecutionLoop 维护 ExecCtx（currentIndex/chain/iterationCounts/visitCounts/pendingApproval）实现 IF/WHILE/审批状态机；executeAgentStep 通过 createProviderAdapter 调用 LLM，使用 callWithRetry 做指数退避重试，区分 CreditExhaustedError / ProviderThrottledError / RunThrottledError；完成后增量或最终写入 Gitee 并更新 state.md / episodes.json。
- `api/workers/swarmWorker.ts` 基于 infra/queue（BullMQ/内存队列）注册 worker，消费 swarm-runs 队列中的 execute 任务，调用 executeSwarmRun 并支持因限流延迟重入队（bypassDedup）。
依赖方向单向：router → service → (giteeService/stateSummarizer/memoryManager/batchService/providerThrottle)，worker 只持有最小 payload {swarmRunId, userId}，所有上下文从 DB 反序列化恢复，保证崩溃可恢复。SSE 事件通过 eventBus.emitEvent 在步骤开始/完成/错误/awaiting_approval 时广播。
