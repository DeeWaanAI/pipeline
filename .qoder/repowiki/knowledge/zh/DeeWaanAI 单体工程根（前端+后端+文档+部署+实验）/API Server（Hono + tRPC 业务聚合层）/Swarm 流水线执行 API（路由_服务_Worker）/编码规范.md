- 路由统一使用 authedQuery 链式声明 .input(z.object(...)).mutation/query，并在内部通过 canAccessProject 校验用户对项目/团队的访问权限。
- 对耗时且可能失败的 LLM 调用统一封装为 callWithRetry，按 credit 错误立即失败、429/限流错误指数退避重试，并在耗尽时抛出专用异常类型。
- 流水线执行状态以 JSON 形式序列化到 swarm_runs.executionState（serializeCtx/deserializeCtx），使 run 可在崩溃或审批后从断点恢复。
- 对外部 LLM 调用的 provider 解析遵循“显式 provider > 项目默认 > 用户首个 provider”的降级策略，并对团队共享场景做 fallback。
- 关键路径（创建 run、审批后重新入队、批量操作）前均先检查 rateLimiter 的 RATE_LIMITS.execute 或 RATE_LIMITS.batch，超限则返回带 retryAfterMs 的错误。
- 通过 eventBus.emitEvent 在步骤开始/完成/错误/awaiting_approval 等节点广播 SSE 事件，前端据此渲染进度与审批 UI。
