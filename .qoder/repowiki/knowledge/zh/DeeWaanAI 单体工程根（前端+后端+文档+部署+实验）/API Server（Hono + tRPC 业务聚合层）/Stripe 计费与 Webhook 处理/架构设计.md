模块按职责分为三层：
- HTTP 入口层（`api/billing-webhook-route.ts`）：基于 Hono 注册 `POST /api/billing/stripe-webhook`，在路由层仅做配置检查、`stripe-signature` 头校验与原始 body 读取，错误统一映射为 400/503/500。
- tRPC 路由层（`api/routers/billing.ts`）：通过 `createRouter` 暴露 `listPlans`、`createCheckout`、`createTeamCheckout`、`teamSeatStatus`、`mySubscription`、`myCapabilities` 等查询/变更，使用 Zod 校验输入并以 `authedQuery` 保护用户态接口；origin 动态推导用于构建 Stripe success/cancel URL。
- 领域服务层（`api/services/billingService.ts`）：集中所有 Stripe SDK 调用与持久化逻辑，维护单例 `Stripe` 客户端并通过 `isBillingConfigured()` 优雅降级；Webhook 处理由 `handleStripeEvent` 统一分发到 `checkout.session.completed`、`customer.subscription.updated/deleted`、`charge.refunded` 等分支，借助 `idempotencyKeys` 表 + `claimEvent` 实现幂等去重；订阅与团队席位分别 upsert 到 `subscriptions` 与 `teamSeats` 表，并通过 `entitlements` 服务授予/撤销能力（含 `team:sync`）。
依赖方向单向：webhook-route → billingService ← entitlements/entitlementSync；tRPC router 同样只依赖 billingService 的 checkout 函数，不直接操作 Stripe。
