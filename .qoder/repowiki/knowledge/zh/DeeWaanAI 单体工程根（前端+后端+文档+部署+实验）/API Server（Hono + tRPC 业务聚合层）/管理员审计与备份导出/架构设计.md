模块按职责分为三层：
- 路由层 `api/routers/admin.ts` 使用自研 `createRouter` + `adminQuery` 中间件，以 zod 校验输入，集中暴露用户/反馈/特性开关/SSO/认证队列/等待名单等管理端点；所有写操作在执行业务变更后统一调用 `logAdminAction` 写入 `adminAuditLog` 表。
- 服务层 `api/services/adminAudit.ts` 仅暴露 `logAdminAction`，采用 fail-open 设计（写入失败只记日志不抛错），保证审计不可阻塞主流程。
- 合规导出 `api/services/auditExport.ts` 独立于路由，通过 `buildAuditLedger` 对 runs/approvals/entitlements/subscriptions/mcpAuditLog/oauthClients/oauthRefreshTokens/users 八张表做 LIMIT/OFFSET 分批扫描（BATCH_SIZE=1000），用 `canonicalJson` 递归排序键生成确定性 JSON，再以 HMAC-SHA256（密钥来自 `AUDIT_EXPORT_KEY` 或回退到 `APP_SECRET`）签名，并提供 `verifyLedgerSignature` 与时序安全的 `timingSafeEqual` 校验；`ledgerToCsvFiles` 按固定 `SECTION_CSV_HEADERS` 输出 CSV。
- 备份子模块由 `api/backup-route.ts` 暴露 `POST /api/admin/backup`，使用 `BACKUP_TOKEN` bearer 鉴权（`timingSafeEqual` 常量时间比较）+ 每 IP 速率限制，再委托 `api/services/backup.ts` 通过 `child_process.spawn('mysqldump')` 配合临时 `my.cnf` 文件执行单事务 dump，gzip 后上传至 S3/R2，并按 `BACKUP_RETENTION_DAYS=7` 清理过期对象；S3 SDK 按需动态 `import` 避免冷启动开销。
依赖方向单向：路由 → services；services 仅依赖 `@db/schema`、`../lib/*` 与外部 SDK，不反向引用路由。
