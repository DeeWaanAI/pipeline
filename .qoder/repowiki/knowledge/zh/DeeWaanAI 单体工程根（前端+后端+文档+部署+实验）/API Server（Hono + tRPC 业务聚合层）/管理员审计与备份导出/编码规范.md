- 所有管理员写操作在业务变更成功后统一调用 `logAdminAction({ adminUserId, action, targetType, targetId, detail, ip })` 记录审计条目，action 使用稳定点号命名如 `user.set_role`、`sso.upsert_connection`。
- 管理端点输入一律通过 zod schema 声明并挂载到 `adminQuery` 链上，分页参数统一为 `page`/`pageSize` 并配合 `LIMIT/OFFSET` 返回 `{ items, total, page, pageSize }`。
- 敏感字段在列表响应中通过 `maskSecret`/`encryptClientSecret` 处理，写入时仅在显式传入时才覆盖加密值，实现 write-only secret 语义。
- 审计导出对大表统一使用 `fetchBatched(page, BATCH_SIZE=1000)` 分批拉取，并以 `asc(id)` 排序保证分页稳定性。
- 审计导出严格过滤敏感字段（prompt/output/tokenHash/secret），仅导出元数据与布尔存在位（如 `hasError`、`hasStripeCustomer`）。
- 对外部进程/SDK 调用采用 try-catch 包裹并降级为日志告警（如 `logAdminAction` 写入失败、备份 pruning 失败），确保主流程不被副作用中断。
