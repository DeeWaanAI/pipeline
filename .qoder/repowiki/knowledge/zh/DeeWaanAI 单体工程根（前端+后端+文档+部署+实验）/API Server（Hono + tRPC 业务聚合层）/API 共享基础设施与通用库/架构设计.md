本模块是 api/server 的横向支撑层，按职责拆分为多个子目录，彼此之间通过清晰的接口边界协作：
- `lib/`：纯函数式工具库（logger、env、rateLimiter、providerThrottle、withTimeout、storage、screenshotUrls、messages、clientIp、adminGuards、observability、vite），被上层 router/middleware 直接依赖；`lib/providers/` 通过 `base.ts` 定义 `LLMProviderAdapter` 统一接口，由 `index.ts` 的 `createProviderAdapter` 按 slug 路由到 openai/anthropic 等实现。
- `infra/`：外部系统抽象层，`redis.ts` 提供带重试退避的懒加载单例 Redis 客户端，`pubsub.ts` 在 Redis 可用时走 ioredis pub/sub、不可用时回退到进程内 EventEmitter，并附带 `queue.ts` 作为消息队列抽象。
- `plugins/`：插件化扩展点，`registry.ts` 维护 `PluginManifest` 数组并通过 `getPluginRouters()` 聚合 tRPC Router；每个插件（如 `circuit-breaker/`）自包含路由、状态和清单，仅反向依赖 registry 暴露的类型。
- `queries/connection.ts`：基于 drizzle-orm/mysql2 的单例数据库连接工厂，区分主库 `getDb()` 与可选只读副本 `getReadDb()`。
- `config/plans.ts`：集中声明 Stripe plan 与能力集，对外暴露 `listPublicPlans()` 供定价 UI 使用。
- `locales/`：按语言分目录的 server-side i18n JSON 资源。
- `types/`：第三方库类型声明垫片（adm-zip、pdf-parse）。
- `testUtils/teamFixture.ts`：基于 mysql2 原始 SQL 的集成测试夹具，创建用户/团队/项目并返回按用户鉴权的 tRPC caller。
依赖方向单向向下：上层 router/middleware → lib/infra/plugins；本模块内部 infra→lib/logger/env，plugins→middleware（router 构建），不反向依赖业务逻辑。
