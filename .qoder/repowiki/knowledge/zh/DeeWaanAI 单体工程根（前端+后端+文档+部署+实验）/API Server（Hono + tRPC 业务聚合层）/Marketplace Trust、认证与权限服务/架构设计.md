模块按职责分为三层：
- Router 层（`api/routers/marketplace.ts`、`certification.ts`、`voucher.ts`）：基于 `createRouter` + `publicQuery/authedQuery/adminQuery` 暴露 tRPC 端点，分别承担 marketplace 列表浏览/测试生成/盲审任务分发、认证报告与徽章查询、代金券管理。
- Service 层（`api/services/cryptoService.ts`、`entitlements.ts`、`entitlementSync.ts`）：提供可复用的领域能力——AES-GCM/CBC 加解密（含主密钥派生）、统一的 `can/grant/revoke/resolveCapabilities` 权限判定引擎、Stripe webhook 触发的购买履约与退款撤销。
- 依赖方向单向：router → service → DB schema（Drizzle ORM），service 之间仅 `entitlementSync` 调用 `entitlements`；`marketplace.ts` 通过 `entitlementCan`、`purchaseCapability` 与权限系统耦合，但反向不依赖。
- 关键边界：认证决策函数（`decideCertification`、`calculateFleissKappa`、`toBlindTaskPayload`）以纯函数形式导出供 tRPC/MCP 复用；`claimNextBlindTask` 使用原子 UPDATE + 重试保证并发安全；`fulfillMarketplacePurchase` 在 Stripe webhook 中做幂等检查与“非 published 即拒绝”的防御性校验。
