模块按 tRPC Router → Service 两层组织：
- `api/routers/` 下每个平台一个 router（`github.ts`、`gitee.ts`、`issues.ts`），统一通过 `createRouter` + `authedQuery` 注册 `.input(zod).query/mutation`，在 handler 中用 Drizzle ORM 校验项目归属（`projects.userId === ctx.user.id` 或团队共享权限）后再调用对应 service。
- `api/services/githubService.ts`、`api/services/giteeService.ts` 是纯 HTTP 客户端，封装对 `api.github.com` v3 和 `gitee.com/api/v5` 的 `getRepo/getFileTree/getFileContent/createOrUpdateFile/listRepos/validateToken` 等调用，内部以 `fetch` + Bearer/token 鉴权头完成请求，错误统一抛错由上层捕获。
- `api/services/giteeSync.ts` 是编排层，组合 giteeService 实现 `syncProjectToGitee`（自动创建私有仓库、批量推送文件并限速）、`fetchFilesFromGitee`（并行拉取多文件），对外暴露结构化结果类型 `GiteeSyncResult`。
- 依赖方向单向：router → service → fetch；数据库访问仅发生在 router 层做权限与状态更新（`lastSyncedAt`、`githubOwner/Repo/Branch`、`giteeOwner/Repo/Branch`），service 不直接访问 DB。
- Gitee 路由额外通过 `isFeatureEnabled('gitee_sync', userId)` 做功能开关，未启用时返回 `TRPCError FORBIDDEN`；同时提供 `getMyData*` / `debugGitee` 等调试接口用于浏览固定 `swarm-studio` 仓库。
