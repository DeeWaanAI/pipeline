- 前后端共享类型与校验统一放在 contracts 目录，通过 @contracts 别名被 frontend_app 与 api_server 引用，避免重复定义
- 数据库模型与迁移集中在 db 目录，通过 @db 别名供业务模块访问，所有变更走 Drizzle migration 而非直连 SQL
- 环境变量通过 .env.example 声明并由 docker-compose.yml 注入，生产环境由 deployment_scripts 的 CI/CD 与 ecosystem.config.cjs 管理
- ESLint + Prettier + Vitest 在根级统一配置，所有子模块遵循同一代码风格与测试规范
