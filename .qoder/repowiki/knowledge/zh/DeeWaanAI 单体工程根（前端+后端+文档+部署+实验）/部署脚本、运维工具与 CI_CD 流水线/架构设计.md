模块按职责划分为四个子目录：
- `deploy/`：面向阿里云 2vCPU/0.5GB 实例的 Bash 安装脚本（`install.sh`、`aliyun-setup.sh`），统一流程为生成随机密钥 → 创建 2GB swap → 安装 Node.js 20 / MySQL 8 / Nginx / PM2 → 写入最小化 MySQL 配置与 `.env` → 执行 `npm run build` + `drizzle-kit push` → 生成 Nginx 反向代理并启用限流（`limit_req_zone`）→ 通过 PM2 启动应用并配置 UFW 防火墙。
- `scripts/`：无框架依赖的独立可执行脚本，分为三类——运维类（`backup-db.sh`、`backup-cron.sh` 使用 `mysqldump --single-transaction` 输出带时间戳的 `.sql.gz` 并保留 7 天）、数据修复/迁移类（`run-migration-*.mjs`、`fix-*.py`、`phase*-patch.py` 直接连接 MySQL 做幂等 DDL/DML）、Smoke 测试类（`smoke-*.mjs` 通过 TRPC batch 协议 `?batch=1` 调用 `/api/trpc` 构造端到端用例，并以 `passed/failed` 计数退出码表示结果）。
- `relay/connector.mjs`：零依赖的出站中继连接器，仅通过 Node 内置 `fetch` 长轮询 `CLOUD_URL/api/relay/poll`，将 `http_proxy` 请求转发到 `LOCAL_URL` 并将结果 POST 回 `CLOUD_URL/api/relay/result`，满足 NAT/严格 egress-only 环境的数据驻留要求。
- `.github/workflows/`：CI 流水线（`ci.yml`）在 Ubuntu runner 上以 Node 20 执行类型检查、i18n 校验、单元测试、生产构建及许可证占位符扫描；集成测试阶段拉起 MySQL 8.0 与 Redis 7 service container 执行真实后端交互；`backup.yml` 通过 cron 定时触发生产环境的 `/api/admin/backup` 端点完成 S3 归档；`site-ci.yml` 专用于站点分支。
依赖方向：所有脚本均自包含，不引用项目源码，仅通过环境变量或命令行参数与目标服务通信。
