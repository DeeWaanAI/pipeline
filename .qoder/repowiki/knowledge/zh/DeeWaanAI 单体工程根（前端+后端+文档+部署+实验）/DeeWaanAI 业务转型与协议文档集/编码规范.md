- 研究协议采用两位数字前缀命名（01-…、05-AMENDMENT-A1-…），主协议与修订案在同一目录下按时间顺序编号管理。
- 工程推进以 PROGRESS.md 中的 `[ ]/[~]/[x]` 任务清单为单一事实源，每项完成后追加日期与变更文件列表，不依赖 git log 追溯状态。
- 跨 Worker 协作通过 FINAL-SPEC.md 风格的“Worker X — Owns (write) / Do NOT touch”边界声明明确写权限范围，避免并发编辑冲突。
- 验收项遵循 ACCEPTANCE.md 的统一模板：目标 → 离线预检 → 在线步骤 → 通过标准，便于第三方系统（Stripe/IdP/桌面客户端/只读副本）逐项核对。
- 功能特性通过 feature flag（如 `companion_mcp`、`store_relaunch`、`teamsync`、`enterprise_sso`、`enterprise_relay`、`gitee_sync`）开关，并以“埋藏（burial）”流程移除已稳定的 flag。
- 网站与 API 文档使用 i18n 键值（en/zh 双份 common.json/server.json），新增文案需同时维护双语并通过 `npm run i18n:check`。
