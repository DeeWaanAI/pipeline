站点采用 Astro 5 + Tailwind CSS 的静态输出模式（`output: "static"`），通过 `astro.config.mjs` 启用 i18n 路由（默认 `en`，无前缀）、Sitemap 集成与 Tailwind 插件。

- 内容层：`src/content/docs` 与 `src/content/blog` 使用 `astro:content` 的 `defineCollection` + Zod schema 定义文档与博客集合，按 `<locale>/<slug>` 目录组织（如 `docs/en/selling.md`），由 `glob` loader 扫描。
- 国际化层：`src/i18n/locales.ts` 集中注册可用语言与默认语言，并提供 `isLocale`、`localePrefix`、`localeTag`、`MULTI_LOCALE` 等工具；UI 文案通过 `src/i18n/ui.ts` 按 locale 加载 JSON 字符串包，组件统一通过 `getUiStrings(locale)` 消费。
- 页面层：`src/pages/[...locale]/` 利用 Astro 动态路由生成所有语言的页面，首页 `index.astro` 按规范分区块渲染并注入 Organization / SoftwareApplication / FAQPage 三段 JSON-LD；文档与博客分别由 `[...slug].astro` 路由渲染。
- 布局与组件：`Base.astro` 作为根布局注入 SEO、Header/Footer、全局样式，并根据 `translated` 标志显示“尚未翻译”的提示条；`Article`、`Docs`、`Legal` 布局继承 Base；通用 UI 组件集中在 `components/`（Header、Footer、LanguageSwitcher、Seo、landing/WaitlistSection）。
- 构建与部署：`Dockerfile` 使用 Node 22 Alpine 构建静态产物到 `/srv`，再以 `caddy:alpine` 镜像运行 Caddy 服务；运行时通过 `sed` 替换 `robots.txt` 中的 `{{SITE_DOMAIN}}` 与所有 HTML 中的 `{{APP_DOMAIN}}`；Caddyfile 配置 gzip/zstd 压缩、哈希资源永久缓存、非哈希资源 must-revalidate、Clean URL 与 404 重定向。
- 依赖方向：pages → layouts → components → i18n；i18n 模块被各层共享但不反向依赖页面；内容集合仅被 pages 读取，形成单向依赖。
